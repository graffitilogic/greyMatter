# greyMatter — Executive Handoff Brief

Prepared September 21, 2026. Project evidence reviewed through the September 20 post-closeout experiments; external comparison sources checked September 21, 2026.

**Project premise.** greyMatter explores whether techniques used to render large game worlds—procedural construction, loading on demand, bounded working sets and selective persistence—can support neural learning and recall on commodity hardware. The intended benefit is to execute a learned network substantially larger than the application's resident memory, activating only the connections needed for a task. The original ambition included testing whether increased effective neural scale could support useful behavior without proportionally increasing hardware requirements. The project chose C#/.NET for an accessible proof of concept, with a GPU port contingent on demonstrated value.

**Current state.** The repository contains a working experimental utility that learns from local text, saves a numeric model, and retrieves associations in a fresh process without rereading its training source. It supports bounded record caches, exact traversal across loaded and unloaded state, checksummed snapshots, and model audits. Readable candidate labels remain external: users supply possible answers, and the model ranks them by activation. This is constrained association retrieval, not language generation or general semantic search. The recovery campaign is complete; subsequent diagnostics and a count-policy comparison are also complete. The latest recorded test suite has **219 passing tests**. The default policy remains the original relay learner; the stronger count policy is an explicit option. No GPU implementation has been undertaken. [Operating instructions and status](README.md), [handoff guide](plan.md).

**Directly demonstrated: memory management works on the tested workloads.** A synthetic learned model contained **4.47 million records and 33.55 million edges**, occupying **1.50 GiB** on disk. Training peaked at **288 MiB process memory**, while the complete resident reference required **1.71 GiB**. Training incurred substantial eviction; separate small-cache tests demonstrated recall through repeated eviction. Paged and resident answers matched exactly, and recall preserved model state. This validates bounded execution of actual learned content, rather than merely reserving a large virtual address range. It does **not** establish operation beyond physical RAM: the workstation had 32 GiB, OS caching assisted performance, and the original full resource-evaluation grid remains incomplete. [Capacity evidence](artifacts/recovery/capacity16/summary.json).

**What the three configurations do.** All use the same numeric record format, packed storage and bounded paging machinery; they differ in how a token is represented and how its outgoing associations are retained.

- **Original relay learner (`source-local`).** A token is represented by eight neurons. Observing one token followed by another reinforces connections from each source neuron to all eight target neurons. Other outgoing associations from that source weaken and may be pruned. This distributes a relationship across a cohort, but spends eight connection slots per successor; with 32 slots per neuron, approximately four complete successors fit. Its forgetting rule further penalizes words with many different successors.
- **Sparse relay variant (`sparse-relay`).** Retains the eight-neuron representation but connects each source neuron to only two deterministically selected members of the target cohort. That reduces connection-slot consumption and increases theoretical successor capacity without enlarging records. Reinforcement and forgetting are unchanged, so freeing slots does not prevent older associations from being erased. It tested a connectivity improvement, not a new learning rule.
- **Paged count policy (`count-baseline`).** Uses one record per token and counts observed transitions to successor tokens, with no decay. Recall distributes activation according to their relative counts. Each record retains at most 32 successors, with a limited displacement rule when full. This is a compact transition-count graph rather than a biologically inspired learner; it tests whether the neural representation and forgetting add value beyond simple statistics through the same infrastructure.

**Directly demonstrated: the tested neural learning layer is inferior to a simpler policy.** The real-data comparison used 40,006 training sentences and 128 supported held-out cues, each with 32 candidates. The September 20 experiment placed a directed-count policy inside the same packed record store, bounded cache and traversal system, making the comparison materially stronger than the earlier uncosted evaluator baseline. Representative model measurements are:

| Configuration | Retrieval MRR¹ | Cues with no output | Model allocation | Training time |
|---|---:|---:|---:|---:|
| Original relay learner | 0.570 | 61/128 | 37.02 MiB | 7.73 s |
| Sparse relay variant | 0.610 | 56/128 | 36.19 MiB | 6.39 s |
| Paged count policy | **0.907** | **10/128** | **4.55 MiB** | **1.49 s** |

¹ Mean reciprocal rank measures how highly the correct candidate is ranked; higher is better. Zero-output cases and ties remain included. The count policy changes both learning behavior and the per-token representation, so its advantage cannot be attributed to one isolated parameter. It also had lower measured query latency. All three configurations retained exact paged/resident results and met the tested memory bound. [Comparison evidence](artifacts/recovery/count-baseline/summary.json).

Diagnostics identified restrictive successor capacity and forgetting triggered by observations of competing successors. Sparse connectivity relieved the storage-slot constraint but failed its registered improvement gate; forgetting continued to limit retention. These findings explain why simply increasing available network storage did not solve recall. The count policy avoids that forgetting mechanism, although its own 32-successor limit still loses some answers. Evidence remains narrow: one corpus, selected supported next-token associations, and seed runs that do not establish independent replication. Broader language utility, emerging behavior and biological fidelity have not been demonstrated. [Diagnostic and experiment ledger](RESULTS.md).

**Reasonable inferences, not established outcomes.** The reusable asset is the learned-graph storage and execution system, which may support other sparse associative workloads independently of the neural policy. Its competitiveness against conventional graph or retrieval systems remains untested. The evidence favors addressing retention and representation before adding hardware: faster execution alone would not restore discarded associations. Profiling attributed approximately 54% of the original learner's instrumented training time to record serialization/checksum work, suggesting an engineering optimization opportunity. That is neither a measured prospective speedup nor a profile of the newer count policy. Cold-storage behavior and OS-cache-inclusive memory limits also remain unresolved.

**Competitive context.** Sparse connectivity, sparse activation and selective loading address different costs: fewer stored connections, less computation per input, and less resident state. The following are relevant alternatives or research comparators, not interchangeable products. Descriptions come from primary sources; greyMatter has not been benchmarked against these systems, and their published performance figures are not directly comparable to its association test.

| Product or experiment | Approach and maturity | Implication for greyMatter |
|---|---|---|
| **Numenta HTM / NuPIC** | Open-source research using sparse distributed representations and continual temporal sequence learning. See the [HTM technical guide](https://www.numenta.com/blog/2019/10/24/machine-learning-guide-to-htm/). Numenta identifies HTM as [legacy research it no longer maintains](https://www.numenta.com/resources/htm/). | A close conceptual comparator for local sequence learning and sparse representations. Study its treatment of temporal context and branching before designing another retention rule. Its learning approach is distinct from greyMatter's demonstrated paging mechanism; no comparative quality or memory advantage is established. |
| **Intel Loihi 2 / Hala Point** | Neuromorphic research hardware using sparse connections and event-driven spiking computation, with memory and processing integrated on specialized chips. [Intel system description](https://www.intel.com/content/www/us/en/newsroom/news/intel-builds-worlds-largest-neuromorphic-system.html). | Relevant to the biological-efficiency ambition, but follows a specialized-hardware route rather than the commodity CPU/storage constraint. greyMatter offers a different deployment approach; it has not demonstrated comparable energy efficiency or neural capability. |
| **DeepSeek-V3** | A released mixture-of-experts language model: its technical report describes 671 billion total parameters, with 37 billion activated per token. This is conditional computation at the expert level. [Technical report](https://arxiv.org/abs/2412.19437). | Demonstrates that total model capacity and per-input computation can differ substantially. Sparse activation alone does not eliminate storage of the full weights or establish bounded-memory training. It addresses general language workloads at a vastly different scale; greyMatter has no demonstrated language-model competitiveness. |
| **Apple, “LLM in a Flash”** | A research inference system that loads model parameters from flash into DRAM on demand, reuses recently active neurons and groups reads for storage efficiency. The paper reports models up to twice available DRAM capacity. [Apple research publication](https://machinelearning.apple.com/research/efficient-large-language). | The closest comparator to the loading-on-demand premise, with published evidence beyond available DRAM that greyMatter lacks. Its focus is inference of pretrained language models; greyMatter's candidate distinction is mutable graph learning plus exact paging. That distinction still needs a useful quality/cost advantage. |

**Competitive assessment.** These examples show that selective activation and memory-aware execution are established directions, so those ideas alone are insufficient differentiation. greyMatter's plausible niche is a small, inspectable C# system for locally updating and traversing persistent associative graphs under an explicit application-memory budget. That is a positioning hypothesis, not a proven market advantage. For investment decisions, the strongest immediate comparator remains the count policy already measured inside greyMatter: it currently delivers better retrieval at lower storage and execution cost. Any next neural-learning experiment should beat that practical reference before seeking comparisons with substantially larger AI platforms.

**Concept value and recommended next steps.** There is credible upside in retaining greyMatter as a compact experimental platform for bounded graph learning and retrieval; there is presently no demonstrated advantage for its biologically inspired learning rules or evidence supporting investment in a GPU-scale intelligence program. A pragmatic continuation would first evaluate promoting the count policy to the supported utility default, then validate that configuration on an additional representative task and under an enforced memory limit that includes OS-cache effects. Profile that configuration before changing checksum granularity. If neural learning remains the research objective, authorize one bounded retention-rule experiment against the count policy with explicit quality, storage and stop criteria. Further investment should depend on a differentiated benefit emerging from those comparisons; otherwise, preserving the substrate and closing the neural-learning line is a defensible outcome.
